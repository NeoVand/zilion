# Intel 8086/8088 coherent-fetch machine

**8086/8088 instruction semantics, validated against hardware 8088 vectors, with coherent fetch.**
This is the declared abstraction for the paper in preparation, status `experimental`,
core version `0.3.0`, compat `0.3`, variant `nmos`, following the 6502 convention.
The descriptor id and package subpath are `i8086`; the vector CLI ISA is `8086`.

The named policy is `prefetch: 'coherent'`: every consumed instruction byte,
opcode, operand, displacement or prefix, is read from current memory when fetched.
There is no prefetch queue and no cycle-timing claim. This deliberately abstracts
both chips' BIU. `prefetch: '8088'` is rejected with a clear error; the former
implementation label `none` is no longer an accepted machine selection. REP
continuations retain their decoded operation and do not fetch instruction bytes.

The pinned hardware data makes this distinction concrete. Each of `90`, `B9`
and `51` has 5,000 initially full queues and 5,000 initially empty queues. After
MOV CX,imm16 (`B9`), all 10,000 final queues are empty. PUSH CX (`51`) ends with
three queued bytes in the initially full cases and one in the empty cases. NOP
(`90`) ends with zero, one or two. A fixed refill at the instruction boundary
cannot reproduce these outcomes. The fixture's final queue is measured after
the first byte of the next instruction has been consumed. Initial queued bytes
agree with RAM in these three files; the README specifies NOP padding for subsequent fetches. Passing
their architectural state does not test execution of stale, self-modified bytes.

## Addressing and initialization

`physical = (segment * 16 + (offset & 0xffff)) & 0xfffff`, then the shared world
maps the physical address to a ring position. Each byte of a word independently
wraps the offset (FFFF to 0000). Physical addresses wrap at 1 MiB before ring
mapping. These two seams differ on odd rings, so both have explicit P=33 tests.
CS=DS=SS=ES=0, IP=0, general registers=0 and FLAGS=F002 unless initialized.
The hardware stack uses SS:SP. A word push decrements SP by two and writes low
then high byte. `firstPushAt(P,t)` places the first low-byte write at t; this
means SP=1 for the last byte on rings of 32 or 64. `topAliases` instead places SP
itself at the requested position. SP and every offset wrap at 16 bits.

The paper and census pin `init.stack: { firstPushAt: 'lastByte' }`, hence
SP=1 on P=32/64 and the first low/high writes at P−1,0. The exploratory
SP=0 convention instead writes at P−2,P−1; it is a different phase, tested
explicitly and not used by the census. DS=ES=SS=CS=0, DF=TF=0, FLAGS=F002
are fixed initial conditions, not immutable registers: executed instructions
may change them. Pointer interventions must leave these initial fields fixed.

INT n/INT3/INTO/divide errors read both IVT words at 0000:4n **before** pushing
FLAGS, CS and the return IP. The IVT aliases ordinary ring bytes. The original
8086 divides return to the following instruction, including on overflow.
IRET pops IP, CS and FLAGS. Reserved flags read as F002, with bits 3/5 clear;
PUSHF/INT mask impossible raw initialization bits, and POPF/IRET normalize stored
flags.
TF is sampled before an instruction; it raises type 1 after the instruction.
A MOV/POP segment load suppresses its own trap boundary. TF also steps REP
iterations. A trapped REP saves the address of only the immediately preceding
prefix, preserving the original chip's documented multiple-prefix restart bug.
Software and TF interrupts use the contract's `syscall` vector-policy category;
divide errors use `div-zero`. There is no external IRQ/NMI input.

HLT reports `halt-insn` with IP past the opcode. `ignore` makes it a no-op.
Host halts park IP on the first prefix. Prefixes are part of their instruction;
a full 64 KiB chain of prefixes raises `bounds` to bound an otherwise endless
single step. I/O with no device reads FF per byte and drops writes; optional
io hooks receive individual byte transactions, including both ports for words.
WAIT without a coprocessor is a no-op; ESC decodes its operand and performs the
memory read without coprocessor effects.

## Instructions and observable choices

The implementation shares addressing, arithmetic, read and store phases rather
than using a separate body for every opcode. It includes the 8086 aliases in the
hardware set (60–6F conditional jumps, C0/C1/C8/C9 returns, F1 LOCK, SETMO/SETMOC,
F6/F7 /1 TEST, FF /7 PUSH and ignored extension bits in segment MOVs and C6/C7).
REP affects MUL/IMUL and IDIV result signs through F1; unsigned DIV ignores it.
All FLAGS bits, including documented undefined ones, are compared. MUL/IMUL
flags come from the final high-half PASS/ADC; DIV/IDIV flags come from the
internal restoring-subtraction sequence. DAA/DAS use hardware adjustment tests
and byte overflow; AAA/AAS adjust AH independently of carry/borrow from AL.
Zero-count memory shifts still write the unchanged operand, as hardware does.

A world step is an instruction or one REP iteration. The decoded REP operation,
source segment, first unit, instruction endpoints and trap restart address are
state fields, so resumed runs do not fetch changed instruction bytes again.
Each continuation invokes the instruction-start and decode hooks. A skipped
continuation cancels REP; host skip consumes the original first unit, decode
skip consumes prefixes plus opcode. `fetchBytes` counts actual instruction-stream
consumption; REP continuation does not fetch again. Thus a fetched-byte budget
can run the remaining finite CX iterations before the next fetch.

## Deterministic undefined-form policy

`hidden_latch: 'zero_ea'` names the existing deterministic abstraction; the core
WGSL is unchanged so the hardware and regression ledgers remain reproducible.
Register LEA/LES/LDS consume the opcode and ModRM, then raise `unimplemented`
(default halt, no invented effective-address history). For FE/FF register far
CALL/JMP (/3,/5), effective offset is freshly zero for each decode. FF takes
the destination IP from the selected word register and the segment word from
selected DS/override:0002. FE takes FF00 | the selected byte register as IP,
and FF00 | memory[default DS or the encoded BP-based SS selection:0000] as CS;
the byte segment read ignores the override, matching the existing undefined
memory-form abstraction. Far CALL pushes old CS then the already-consumed return
IP (FE writes one byte per push, FF two), after reading the target. There is no
persistent hidden EA or tmpB state. Prior effective addresses, dispatch partition
and uninitialized GPU private memory cannot affect the result.

This is a pure function of memory and the declared state, not a claim to predict
hardware whose hidden tmpB initialization is absent from the vectors. The ledger
rule remains narrowly limited to CS/IP and unlisted reads for these forms; it
never excuses writes, values, flags or other registers. The census includes
these deterministic forms and labels mechanisms from their actual traces.
All other documented and undocumented aliases described above execute; forms
not decoded by this 8086 core raise `unimplemented` (no 80186 instruction set).
No third-party emulator code was used.

## Validation and provenance

Vectors are data from SingleStepTests/8088, MIT, commit
`aea84484abc79d09639d855b7b0ab32bc9e4dbeb`. The v2 and v2_undefined gzip files total
804,548,868 bytes; all 342 selected files including documentation total 804,632,471
bytes. `tools/fetch_8088.py` inventories before downloading, refuses compressed
sets over 3 GB, downloads no upstream tools, preserves gzip and verifies each Git
blob SHA-1. `PIN.json` beside the local vectors records the file hashes and sizes.
Python readers run with `-I`. Fetch and reproduction commands are in
[Testing](TESTING.md#intel-8088-architectural-vectors); attribution is in
[THIRD_PARTY.md](../THIRD_PARTY.md).

The adapter merges sparse final registers with the complete initial state,
extracts memory writes and ports from latched ALE/T3 bus transactions, and checks
all register bits without flag masks. It compares a zero REP latch at the end of
each full instruction. Queue contents and per-cycle timing are explicitly outside
this ledger. World probes cover rings 32, 33, 64, IVT/stack aliasing, both seams, TF,
REP resumes, HLT and budgets. The B9 51 tiling self-writes unchanged on P = 32 and P = 64
under zero registers and firstPushAt:lastByte for 128 steps. Separate encounters
with a NOP partner reach its first unwritten byte, demonstrating the open channel.

## Gate 1 checks

`test/world/cases_i8086.mjs` tests P=32/64 encounters and bootstrap into zero
and the 16-member frozen seeded random panel; SP=0 versus lastByte; PUSH SP's decremented value;
low-before-high order (including both offsets aliasing one byte); aliased IVT
reads before stack writes; segment/offset seams; fixed initial segments/DF/TF
and explicit backward strings; TF and segment-load boundaries; CX=0 REP;
iteration budgets and resumed decoded REP after overwriting its own code;
coherent next-opcode, immediate and prefix changes; deterministic zero-EA far
transfers and excluded forms; and undocumented aliases. Bootstrap writes are
measured separately from a completed full-tape copy in the census. A pre-tiled
pair alone is not a bootstrap result.

At 128 steps, B9 51 bootstraps exact tilings into zero partners on P=32/64
and the affine-pattern partner on P=32; the same affine-byte construction on
P=64 gives a damaged tape. The tests pin both outcomes. Availability and
a pre-tiled self-write are not a claim of partner-independent bootstrap.

The standalone regression suite also pins B9 51 at 128 steps against the 16
frozen hash-generated census partners on each ring. Their complete final
memories, halt/step counts, byte-write totals and fetch maps are checked.
Exact bootstrap up to cyclic phase occurs in 13/16 partners at P=32 and
6/16 at P=64. Original-phase matches are 12/16 and 6/16 respectively; the
other outcomes are retained in the fixture, not replaced with tiled partners.
