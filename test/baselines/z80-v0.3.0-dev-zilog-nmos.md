## Analysis

**Status: full baseline of the 0.3 Z80 core, variant `zilog-nmos`** (`compat: '0.3'`, the Q latch; io hooks on), on
the same inputs as `z80-v0.3.0-dev.md`: 1,604,000 SingleStepTests/z80 tests (commit
`ebe1875d48f374bcfd4b505d8eb8ee751568b5f7`), 384 wasted-prefix vectors and 86 R/WZ probes. Rules:
`test/vectors/z80/expected-0.3.0-zilog-nmos.json`. Only this report is committed: the ledger JSON differs from the
default core's only in the Q column, which is empty here (re-create it with the command in docs/TESTING.md).

### Findings

1. **Unexpected divergences: none**, over 1,604,470 tests, with one rule: **EI-P** (1,203,721 tests), the interrupt
   latches. Every architectural field of every test matches (100.00%), and so do WZ, IM and Q.
2. **Q.** Q = F after an instruction that writes F, else 0. The vectors confirm the classification instruction by
   instruction: POP AF, EX AF,AF', LD I,A, LD R,A, OUT (C),0, RES/SET and IM leave Q = 0; LD A,I/R, IN r,(C), every
   ALU, rotate, BIT and block instruction set it.
3. **A DD/FD prefix clears Q.** The prefix is an instruction cycle of its own that leaves F alone, so a DD- or
   FD-prefixed SCF/CCF sees Q = 0 (885 tests in `dd 37`, `dd 3f`, `fd 37`, `fd 3f`). The first run of this variant
   missed exactly these; the 0.2.0 ledger's Q-XY rule had found the same effect from the other side.
4. **The harness can still fail.** Three self-test mutants on this variant (SCF ignoring Q, Q kept by instructions that leave F alone, Q kept after
   a prefix) each produce unexpected divergences.

### Determinism

The plain run and a run with `--repeat 2` gave the same ledger SHA-256.
