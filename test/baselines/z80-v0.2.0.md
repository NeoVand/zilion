**WZ.** MEMPTR (WZ) is not modelled in 0.2.0. The harness passes the field through, so it diverges wherever the instruction changes WZ. Source: design §5.3 and Appendix B (WZ).
Example: `02 0000` (bytes `02`): `wz` 0xa21f → 0xa045.

**Q.** The Q latch (the flags written by the last instruction) is not modelled; passed through. Source: design §5.4 and Appendix B (Q-XY).
Example: `00 0007` (bytes `00`): `q` 0x00 → 0x55.

**EI-P.** The interrupt-acceptance latches (EI delay; LD A,I/R parity bug) are not modelled: Zilion has no interrupts. Passed through. Source: SingleStepTests/z80 README (fields ei, p).
Example: `00 0003` (bytes `00`): `p` 0x00 → 0x01.

**IM.** IM 0/1/2 (and their mirrors) are executed as NOPs; IM is not modelled. Source: design §5.4 and Appendix B (IM).

**R-WASTED.** A DD/FD prefix followed by DD, FD or ED is wasted: one step, one M1 cycle, R + 1. Zilion 0.2.0 counts the follower's M1 too and backs PC up, so the follower is counted again next step: R + 2 per wasted prefix. Explained only where the vector says R + 1 and Zilion gives R + 2. SingleStepTests has no such vectors; these come from the analytic set (tools/z80-analytic-vectors.py). Source: design §5.2 and Appendix B (R-WASTED).
Example: `dd dd 0000` (bytes `dd dd`): `r` 0x00 → 0x01.

**BIT-HL-XY.** BIT n,(HL) takes F3/F5 from the operand; a Z80 takes them from WZ bits 11 and 13 (MEMPTR leak). Explained only where the vector follows the WZ formula and Zilion the operand formula. Source: design §4.4 (bit-mem-f3f5), §5.3, Appendix B (BIT-HL-XY).

**Q-XY.** SCF/CCF take F3/F5 from A only; on a Zilog NMOS Z80 they are ((Q xor F) or A) & 0x28, and Q is not modelled. Explained only where the vector follows the NMOS formula and Zilion the A-only formula. Source: design §5.4 and Appendix B (Q-XY).
Example: `37 0009` (bytes `37`): `f` 0xa9 → 0x81; `q` 0xa9 → 0x00.

**REP-XY.** LDIR/LDDR/CPIR/CPDR when repeating: on a Z80, YF = PC.13 and XF = PC.11 (PC = the ED byte); Zilion keeps its non-repeating formula from the data. Explained only where the vector follows the PC rule and Zilion its data formula. Source: design §5.4 and Appendix B (REP-XY); redcode Z80 block flags test.

**REP-IO-FLAGS.** INIR/INDR/OTIR/OTDR when repeating: on a Z80, YF = PC.13 and XF = PC.11 and H and P/V are further adjusted; Zilion keeps its non-repeating formulas. Explained where the vector's X/Y follow the PC rule and Zilion's X/Y its B formula; H and P/V are covered by the mask only (no formula checked). Source: design §5.4 and Appendix B (REP-XY); redcode Z80 block flags test.

**IO-IN-A.** IN A,(n): port reads return 0 in 0.2.0 (no I/O device). Explained only where the vector's port supplies a non-zero value, the vector's A holds it and Zilion's A is 0. Tests whose port reads 0 must match. Source: design §5.4 and Appendix B (IO).

**IO-IN-C.** IN r,(C) and IN (C): the port reads 0 in 0.2.0. Explained only where the port value is non-zero, the vector's target register holds it, Zilion's holds 0 with the flags of a 0 read (Z, P/V; C kept), and every other register matches. Source: design §5.4 and Appendix B (IO).

**IO-IN-BLOCK.** INI/IND/INIR/INDR: the port reads 0 in 0.2.0, so the byte stored at (HL) and the flags derived from it differ. Explained only where the port value is non-zero, the vector stores it at (HL), Zilion stores 0 with its flag formula for a 0 read, and no other address differs. Source: design §5.4 and Appendix B (IO).

**IO-IN-PORT.** The 0.2.0 core never calls a port-read hook, so the vector's listed port read does not happen. Source: design §5.4 and Appendix B (IO).

**IO-OUT-PORT.** The 0.2.0 core never calls a port-write hook, so the vector's port write does not happen. Source: design §5.4 and Appendix B (IO).

## Analysis

**Status: partial baseline.** Only 203 of the 1,604 SingleStepTests/z80 files were available when this was
generated: the base page from `00` to `ca`. The download stopped at `v1/cb 00.json`, the first file name that
contains a space. The fetcher did not URL-quote paths, so every later prefixed file fails.

Not yet checked against any vector:

- base `cc`–`ff`;
- the whole CB, ED, DD, FD, DDCB and FDCB pages.

Nine of the fourteen expected rules therefore have no hits. That means *not exercised*, not stale.

Once the full set is present (fetch with `tools/fetch-vectors.py`, which quotes paths and verifies git blob hashes),
regenerate with the command in docs/TESTING.md ("Baselines"). That takes about 5 s for 1.6 M tests on the M4
(measured on a 1,604-file stand-in).

### Findings on what ran

1. **Unexpected divergences: none**, over 203,000 SingleStepTests vectors and 384 analytic vectors. The harness can
   report unexpected classes: the self-test's mutated cores (dropped R increment, wrong PUSH byte, wrong INC flags,
   SCF X/Y and BIT n,(HL) X/Y errors that are not the Q or WZ effect, DJNZ never taken, HALT not halting, a NOP that
   reads or writes memory) each produce them, with reproducers.
2. **Architectural fields.** 202,552 of 203,000 SingleStepTests vectors match on every architectural field.
   The other 448 are SCF (`37`) and CCF (`3f`), F3/F5 only (rule Q-XY). Every one passed the model check:
   - the vector follows ((Q xor F) or A) & 0x28;
   - Zilion follows A & 0x28.

   All 2,000 SCF/CCF vectors follow the NMOS Q formula; the other 1,552 happen to agree with A & 0x28.
3. **HALT.** All 1,000 `76` vectors match once Zilion's parked PC is mapped to PC + 1 (HALT-PC). No other file set
   the halted flag.
4. **R.** No SingleStepTests divergence: R + 1, bit 7 kept, for every base opcode. The analytic wasted-prefix
   vectors confirm R-WASTED: in all 384 (DD or FD followed by DD, FD or ED), Zilion gives R + 2 where the hardware
   rule gives R + 1, PC + 1 matches, and nothing else differs.
5. **Memory and ports.** No divergence in any test, and no unlisted read or stray write anywhere: in 00–CA, Zilion
   reads and writes exactly the addresses the reference lists. This subset contains no port instruction (`d3`/`db`
   are absent).
6. **WZ (MEMPTR, internal).** WZ changes in exactly 26 files: `02 09 0a 10 12 18 19 1a 20 22 28 29 2a 30 32 38 39
   3a c0 c2 c3 c4 c7 c8 c9 ca`. These are exactly the WZ-writing instructions of the design's MEMPTR table (§5.3) in
   this range:
   - LD A,(BC)/(DE), LD (BC)/(DE),A;
   - LD A,(nn), LD (nn),A, LD HL,(nn), LD (nn),HL;
   - ADD HL,rr;
   - JR, JR cc, DJNZ;
   - JP nn, JP cc, CALL cc;
   - RET, RET cc;
   - RST 00.

   Every other file leaves WZ unchanged. For these opcodes, the vectors and the §5.3 table agree on *which*
   instructions write WZ. The values are checked once WZ is modelled (work item 3).
7. **Q and EI/P (internal).** They diverge in every file, as expected with no model:
   - SingleStepTests sets Q to F after a flag-writing instruction and to 0 otherwise;
   - it clears `ei` and `p` after every instruction in this subset. EI and LD A,I/R, which set them, are absent.

### Determinism

The baseline was generated twice, and both runs gave the same ledger SHA-256 (Provenance table). `--repeat 2`
(every dispatch twice, byte-compared) and the `full` memory model (64 KiB per lane) gave identical per-file ledgers
and identical raw GPU digests.
