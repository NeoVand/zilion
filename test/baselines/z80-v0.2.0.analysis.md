**Status: full baseline.** All 1,604 SingleStepTests/z80 `v1` files ran (1,604,000 tests, data pinned at commit
`ebe1875d48f374bcfd4b505d8eb8ee751568b5f7`), plus the 384 analytic wasted-prefix vectors in `test/vectors/z80/analytic`.
The run was made on the integration branch (package `0.3.0-dev`). Its Z80 core text is byte-identical to the 0.2.0
release: the core SHA-256 in the Provenance table is the one emitted at tag `v0.2.0`. This is therefore the 0.2.0
core's baseline. The expected-rules file is selected by that SHA-256 (`core_sha256`), not by package version.

### Findings

1. **Unexpected divergences: none**, over 1,604,384 tests. The harness can report them. Each of the self-test's ten
   mutated cores produces an unexpected class with a reproducer. The mutants are:
   - a dropped R increment;
   - a wrong PUSH byte;
   - two wrong INC flags;
   - SCF X/Y not following Q;
   - BIT n,(HL) X/Y not following WZ;
   - DJNZ never taken;
   - HALT not halting;
   - a NOP that reads memory, and a NOP that writes memory.
2. **Architectural fields.** 1,557,549 tests (97.08%) match raw on every architectural field. The other 46,835 fall
   under three kinds of documented deviation:
   - **Undocumented flag bits F3/F5 (X/Y) only.** Three rules:
     - Q-XY: SCF/CCF, 2,210 tests in 6 files;
     - BIT-HL-XY: BIT n,(HL), 5,983 tests in 8 files;
     - REP-XY: repeating LDIR/LDDR/CPIR/CPDR, 2,959 tests in 4 files.

     No documented flag and no register differs in these tests.
   - **R after a wasted DD/FD prefix (R-WASTED).** In all 384 analytic tests Zilion gives R + 2 where the hardware
     gives R + 1. This is a real core bug.
   - **No I/O device and no interrupt mode.** Zilion 0.2.0 calls no port hook: port reads return 0 and port writes
     vanish. This affects 30 files: IN/OUT, the block I/O instructions and their repeating forms. IM 0/1/2 execute
     as NOPs (5,299 tests in 8 files).
3. **The partial baseline's gap, closed.** Run on 203 files, the first baseline was clean. The first full run then
   left 885 tests unexplained: SCF/CCF after a wasted prefix (`dd 37`, `dd 3f`, `fd 37`, `fd 3f`), F3/F5 only. The
   cause was in the rule, not the core. On a Z80 the wasted prefix executes as a flag-neutral instruction of its own,
   so it clears Q. SCF/CCF then take X/Y from (F or A) & 0x28, not ((Q xor F) or A) & 0x28. Both reproducers were
   checked by hand. The Q-XY predicate now sets Q = 0 after a wasted prefix. Every one of the 885 then follows the
   formula. A harness unit test pins the case on SingleStepTests test `DD 37 0008`.
4. **Internal columns.** None of these is modelled in 0.2.0, so each diverges wherever the instruction changes it:
   - WZ (MEMPTR): 767,839 tests;
   - Q: 1,155,985 tests;
   - EI/P: 1,203,721 tests.

### What can reach an Algocell soup

A soup has no I/O device and no interrupts, so the I/O and IM rows describe the environment, not the CPU. Three
deviations can change a soup's bytes:

- **X/Y through `PUSH AF`.** An X/Y difference reaches memory only through `PUSH AF`, or through `EX AF,AF'` and
  then a push.
- **R through `LD A,R`.** The wasted-prefix R difference reaches a register through `LD A,R`.
- **A 0 where a bus would float.** A soup's `IN` reads 0, where an unconnected bus would usually float high.

Whether any published soup result depends on them is a separate question, for the impact study that runs before Algocell moves to a fixed core. This
baseline only establishes what the deviations are and where they occur.
